# imjin

임진 해전 — 임진왜란 해전을 다룬 3D 웹 전략 게임 (WebGPU · three.js · React).

- 플레이: https://imjin1592.com
- 개발: `npm install` → `npm run dev` (http://127.0.0.1:5291)
- 배포: `main` 브랜치에 푸시하면 GitHub Actions가 빌드 후 S3 + CloudFront로 자동 배포합니다.
- 코드 검증: `npm run typecheck` → `npm test` → `npm run build`. `npm test`는 전투·전역·렌더 수명 관리·네트워크·잘못된 서버 입력 회귀를 실행합니다.
- 브라우저 검증: 빌드 후 `npm run preview -- --host 127.0.0.1 --port 5291 --strictPort`를 실행하고, `npm run e2e`와 `node scripts/test-campaign.mjs`를 실행합니다. 후자는 함대 전멸 후 건조·재출격과 결과 화면까지 확인합니다.
- 번역 검증: `node scripts/i18n-check.mjs --strict`.
- 서버 배포 검증: `MP_INSTANCE_ID`가 설정되면 웹 배포 전에 서버의 protocol과 Git revision을 확인합니다. 미설정이면 protocol만 검사하며 서버 코드 배포는 별도로 필요합니다.

온라인 랭크전은 사람끼리 1:1 한려수도 쟁탈전으로 진행합니다. 조선·일본·명 중 어느 진영이나 선택할 수 있고 같은 진영끼리도 대전합니다. 초기 점수는 1000, 배치는 10판이며 이후 Elo로 점수를 갱신합니다. 역사 전투·AI·일반전은 점수에 반영하지 않습니다. 랭크 계정은 브라우저에 저장되며 개인 복구 코드로 옮길 수 있습니다. 복구 코드를 가진 사람은 계정을 사용할 수 있으므로 공개하지 마세요.

일반 쟁탈전·온라인 일반전·전역에는 함선 수와 함대 전력 상한이 없습니다. 쟁탈전의 각 진영은 같은 초기 자금으로 시작하고, 자금과 선소를 확보하면 계속 증원할 수 있습니다. 일반전의 새 건조·건설·증축 시간은 기존의 36%이며 선소 1·2·3단계는 각각 2·3·4척을 동시에 건조합니다. 군영은 단계마다 승조원을 초당 0.8% 충원하고 선소 건조를 지원하며, 수리소는 선체 1%·승조원 0.2%를 회복합니다. 포대·창고·봉수대의 증축은 각각 포격·보급·거점 장악을 강화합니다. 완성된 함선에 집결 지점을 지정할 수 있습니다. 전역의 새 건조는 64초당 1턴, 건물 증축은 50초당 1턴으로 환산해(판옥선 1턴, 거북선 2턴, 대부분의 증축 1~2턴) 휴식과 수리도 빨라졌고 선소 병렬 칸은 4·6·8칸입니다. 새로 시작하는 전역은 시작 함대·포구 수비대·증원이 이전의 2배입니다. 기존 저장 작업의 기간과 지불 비용은 보존합니다. 쟁탈전의 거점 패널에 있는 "자동 건설"은 혼자 하는 전투에서 켜진 채 시작해 군영·선소·포대·수리소·창고·봉수대와 증축을 알아서 주문합니다(주력함 한 척 값을 남기고 2초에 한 건이며 서버는 평소의 건설 명령처럼 검증합니다). 온라인 일반전에서는 꺼진 채 시작해 직접 켜야 하고 랭크에서는 보이지 않습니다. 협선은 정찰 외에 90m 안의 아군 3척을 돌며 승조원·탄약·선체를 조금씩 회복시키고(한 척은 한 협선에게만 보급받음, 최근 8초 안에 피격된 함선 제외) 컴퓨터의 협선은 가장 지친 아군을 따라다닙니다. 랭크와 역사 해전에서는 이전과 같습니다. 랭크는 지휘관당 36척·전력 10000과 기존 생산·수리 규칙을 고정해 사용합니다.

전역 함대 합류의 24척 제한과 3D 해전의 30척 제한을 제거했습니다. 전투에 참여한 모든 함선이 직접 출전하고 결과에 반영됩니다. 전역 군영·선소·포대 등은 해전의 시설과 단계로 이어집니다. 역사 시나리오의 출전 함선과 전투 수치는 유지하며, 대표 함선인 거북선은 게임 내 선체와 물리 크기를 길이 50.4m·폭 14.4m로 확대했습니다(판옥선 40m·11.5m). 이는 게임의 미술 방향이며 실제 역사 치수를 주장하는 값이 아닙니다.

장수 초상화 18종은 조선의 두정갑·투구, 일본의 판금 갑옷·가부토, 명의 붉은 갑옷·망토를 구분하는 영화 장면풍 이미지입니다. 생성 프롬프트와 파일 해시는 `scripts/portrait-art-direction.json`에 기록합니다. 거북선 용머리는 사용자 승인 이미지로 Meshy 7.1에서 1회 생성한 원본을 보존하고, 승인된 형태를 로컬에서 1,499·499·179삼각형 LOD로 최적화했습니다. 출처·승인·비용·해시는 `assets-src/dragonhead-2026-10-11/`에 있습니다. 함대 선회 항적, 젖은 해안 암반과 낮은 해무는 기존 관측 규칙과 함께 렌더링합니다.

빠른 생산 규칙에 맞춰 기본 동맹 전역의 진영 소득 배율을 조선 0.7·일본 1.18·명 2.3으로 조정했습니다. 개발 시드와 분리한 500개 시드의 보통 난이도 AI 전쟁에서 조선·일본·명 승률은 30%·40%·30%, 무승부·미종료는 0건이었습니다. 이는 해당 전역 AI 정책의 검증이며 실시간 대전이나 사람 간 균형을 입증하지 않습니다.

새로 시작하는 사람 플레이 전역에서는 조선을 선택하면 동맹 명, 명을 선택하면 동맹 조선의 시작 함대·무료 함대 증원을 약 40%, 진영 수입을 35% 줄입니다. 플레이어 함대와 수비대·유료 건조는 줄이지 않으며, 일본 선택 시 적 연합군에는 적용하지 않습니다. `allySupport.version = player-ally-v1`을 새 저장에 기록하고 무료 증원의 소수분을 다음 증원으로 이월합니다. 기존 저장에는 이 규칙을 추가하지 않습니다. 동맹 파기 시 이후 소득·증원 감축은 중단됩니다.

전역은 목포진·녹도진·방답진 등을 포함한 40지역과 한국 해안 36포구를 사용합니다(고금도·회령포·순천 왜교성·서생포·울산 등 15곳을 더했습니다). 새 포구의 사료 링크는 지역 데이터에 기록하고, 기존 12지역·25지역 저장은 함선·항로·자금·RNG를 보존하며 확장하고, 새로 들어온 포구는 성장으로 치지 않습니다. 전역 지도는 역사 전투 선택 화면과 같은 실제 고도 자료(DEM)로 만든 남해안 3D 지형이며, 투시 카메라로 높은 시점에서 지평선이 보이는 낮은 시점까지 기울여 볼 수 있습니다. 땅은 고도와 경사에 따라 들·숲·바위·모래로 칠해지고, 바다는 수심에 따라 청록에서 짙은 남색으로 변하며 파도와 햇빛 반사가 천천히 움직이고, 멀리는 안개로 흐려집니다. 가까이 가면 숲에 나무가 심어지고(카메라 거리에 따라 세 단계, 군영 둘레는 비웁니다) 정착지와 함대가 그 땅 위에 섭니다. 조작은 끌어서 땅 이동, 휠로 커서 위치 확대·축소, 오른쪽 버튼으로 끌어 회전·기울이기, 방향키·WASD 이동, Q·E 회전, R·F 기울이기, 지도 옆 버튼으로 회전·기울이기이고, 터치에서는 한 손가락으로 끌고 두 손가락으로 확대·이동·회전합니다. 마커·카드·박스 선택은 같은 투시 투영을 쓰며 카메라 상태와 장면이 어긋나지 않는지 테스트합니다(`scripts/test-world-camera.mjs`, `scripts/test-map.mjs`). 폰과 터치 전용 태블릿은 3D 없이 같은 지도 이미지를 씁니다. 지도 위에는 세력별 영토 색과 군영 단계가 보이는 정착지 배지가 있고, 가까이 확대하면 그 군영의 조감도가 도시 카드로 나옵니다(폰은 더 크게 확대할 때만 나옵니다). 함대를 고르면 갈 수 있는 적의 포구가 강조되고 그 포구를 한 번 누르면 바로 공격하며(이동과 공격이 따로 없습니다), 우리 편 포구로 옮길 때만 이동을 눌러 항로를 고릅니다. 갈 수 있는 항로는 굵은 점선과 방향 표시로 강조됩니다. 위쪽의 "자동 건설"은 새 전역에서 켜진 채 시작하며, 켜 두면 턴을 마칠 때 군영·선소·포대·수리소·창고·봉수대를 알아서 짓고 올립니다(다음 턴 유지비와 150냥 중 큰 쪽을 남기고 한 턴에 최대 두 건, 함선은 짓지 않습니다). 끈 전역은 켜지 않은 때와 주사위까지 똑같이 진행되고 옛 저장은 꺼진 채 열립니다. 데스크톱과 태블릿에서는 섬 위에 군영 단계에 따라 세력마다 다른 3D 건물이 서고 함대가 있는 항구에는 작은 배가 떠 있습니다. 조선 군영은 목책과 초가에서 기와·선착장, 성벽·봉수대·포대, 선소로 자라고, 일본 군영은 흰 회벽·검은 지붕·붉은 깃발의 왜성(장막 진지에서 3층·4층 천수각까지), 명 군영은 벽돌 성벽·회록색 지붕·노란 깃발의 네모난 보루(목책 망루에서 각루·포대·봉화대까지)입니다. 군영 둘레의 세력 색 테두리와 깃발로 기본 확대에서도 누구 포구인지 보입니다. 항해 중인 함대는 항로 위 제자리에 깃발 단 작은 함대로 서고(섬에 걸리면 가까운 물길로 비켜 섭니다), 턴을 마친 뒤의 움직임 재생에서는 배들이 항로를 따라 항적을 남기며 나아갑니다. 도시 카드는 서로 겹치거나 다른 포구 표식을 가리지 않는 것만 보이고, 선택한 포구·마우스를 올린 포구·내 포구·군영 단계 순으로 자리를 얻습니다. 지형 자료의 출처는 `public/ui/TERRAIN-CREDITS.txt`에 있습니다. Ctrl(Cmd)+드래그나 지도 옆 "박스 선택" 버튼으로 사각형 안의 함대와 포구 수비대를 한 번에 고르고(Shift를 더하면 추가), 포구 마커를 눌러 수비대를 일괄 선택에 넣고 뺄 수도 있습니다. 고른 병력은 모두 도달할 수 있는 목적지를 한 번 눌러 바로 출동하며, "도착하면 합류"를 켜면 같은 지역에 모인 함대가 하나로 합쳐집니다. 한 포구에 있는 함대는 "모두 합류"로 한 번에 합칩니다. 빈 지도를 눌러도 선택은 유지되고 Esc나 "선택 해제"로 지웁니다. 수비대는 실제 함선과 승조원 상태를 유지한 출동 함대가 됩니다. 지역 전투의 지형은 지역 표식 주변 16 km의 실제 고도(`public/terrain/<지역>.dem`, 출처는 `public/ui/TERRAIN-CREDITS.txt`)로 만들고, 지역마다 숲·바위·논·마을·봉수의 구성이 다릅니다. 자료에 해저 수심이 없어 바다는 해안에서 멀어질수록 깊어지게 만든 값이며 실제 수심이 아닙니다. 지역 전투에서 일본과 중국 지역의 가옥은 아직 조선식 초가·기와 모델입니다.

비역사 해전의 주력함 시야는 900m, 각 진영 정찰함(협선·고바야·명 소형선)은 1600m이며 같은 팀이 관측을 공유합니다. 섬이 시야를 가리고 밤과 안개는 관측 거리를 줄입니다. 완성된 봉수대는 해안 시야를 넓힙니다. 온라인 서버는 관측되지 않은 적의 위치·시설·생산 정보를 전송하지 않습니다. 전역에서도 주력함은 인접 항로, 정찰함은 두 항로의 정보를 확인합니다. 전역 AI도 같은 시야를 사용하고 미정찰 포구는 공개된 지역 가치로 추정합니다. 전역 현황의 적 함선 수는 관측한 함대만 집계하고 비공개 전력이 포함된 점수는 전쟁이 끝나면 공개합니다.

일반 해전은 전투 시드로 낮·노을·밤·안개·풍랑과 바람을 선택하고 서버와 화면이 같은 파도·시정·조류를 사용합니다. 여수·목포의 회오리와 전용 진형은 지형에 맞춘 게임 설계이며 당시의 실제 조류나 진형을 재현했다고 주장하지 않습니다. 충돌 속도와 진입각, 수선 아래 피격은 선체·승조원·침수·추진·조타 손상에 영향을 줍니다. 승조원의 배수와 수리소에서 복구합니다. 랭크는 고정된 기상과 조류 없는 조건을 사용하고 역사 시나리오는 기존 조건을 유지합니다.

전투 조작: `Ctrl+A` 전체 선택, `Ctrl+1~8` 부대 지정, `Shift+1~8` 선택 함선 추가, `1~8` 부대 선택, 같은 부대를 두 번 선택하면 시점 이동. 왼쪽 부대 패널에서 지정·이름 변경·경로 예약을 할 수 있으며 휴대폰에서는 패널을 접어둘 수 있습니다. `Shift+우클릭`은 최대 16개의 이동 지점을 예약합니다. 바다에 내린 이동 명령은 금빛 깃발로 8초간 표시하고 예약 지점은 번호가 붙은 하늘색 깃발로 구분합니다. 새 이동·정지·공격·진형 명령은 예약을 지웁니다. 함선을 고른 뒤 적 함선이나 적 거점 시설을 왼쪽 클릭하면 바로 공격·포격하고(`Shift`·`Ctrl`+클릭은 선택만 합니다), 바다는 우클릭으로 이동합니다. 진형은 `Alt+1~4`, 속력은 `Alt+5~7`입니다. 온라인의 이동 예약과 건설은 서버가 검증하고 실행합니다.

비역사 모드는 `src/sim/competitive.ts`의 경쟁용 함선 수치를 사용하고, 역사 전투는 기존 카탈로그와 시나리오 보정을 사용합니다. `node scripts/balance-competitive.mjs --cohort=holdout --mode=conquest --seeds=8 --map=hallyeo,gyeonnaeryang --comps=default,heavy,mobile --out=shots/balance/holdout.json`으로 동일 자원·양쪽 출발 위치를 바꾼 AI 검증을 재현합니다. AI 승률은 사람 간 완전한 균형을 입증하지 않습니다. 실제 랭크전은 개인 서버 기록의 복사본에 `node scripts/report-ranked.mjs --file=<ranked.jsonl>`을 실행해 진영별 결과와 출발 위치 편향을 확인합니다. 기권·접속 종료·무효 경기는 전투 밸런스 통계에서 분리됩니다.

서버 랭크 기록은 `RANKED_STORE`로 지정한 JSONL 파일에 저장합니다. 운영 파일은 `/opt/imjin/data/ranked.jsonl`이며 서버 번들과 함께 덮어쓰지 않습니다. 기록 파일은 계정 인증 해시를 포함하므로 비공개로 관리하고, 변경 전 백업하세요. 결과를 두 사람에게 반영하는 기록을 디스크에 확정한 뒤 점수를 알립니다. 서버 재시작 중 미완료 대전과 로딩 실패는 무효 처리됩니다.
