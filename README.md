# imjin

임진 해전 — 임진왜란 해전을 다룬 3D 웹 전략 게임 (WebGPU · three.js · React).

- 플레이: https://imjin1592.com
- 개발: `npm install` → `npm run dev` (http://127.0.0.1:5291)
- 배포: `main` 브랜치에 푸시하면 GitHub Actions가 빌드 후 S3 + CloudFront로 자동 배포합니다.
- 코드 검증: `npm run typecheck` → `npm test` → `npm run build`. `npm test`는 전투·전역·렌더 수명 관리·네트워크·잘못된 서버 입력 회귀를 실행합니다.
- 브라우저 검증: 빌드 후 `npm run preview -- --host 127.0.0.1 --port 5291 --strictPort`를 실행하고, `npm run e2e`와 `node scripts/test-campaign.mjs`를 실행합니다. 후자는 함대 전멸 후 건조·재출격과 결과 화면까지 확인합니다.
- 번역 검증: `node scripts/i18n-check.mjs --strict`.
- 서버 배포 검증: `MP_INSTANCE_ID`가 설정되면 웹 배포 전에 서버의 protocol과 Git revision을 확인합니다. 미설정이면 protocol만 검사하며 서버 코드 배포는 별도로 필요합니다.

온라인 랭크전은 사람끼리 1:1 한려수도 쟁탈전으로 진행합니다. 조선·일본·명 중 어느 진영이나 선택할 수 있고 같은 진영끼리도 대전합니다. 초기 점수는 1000, 배치는 10판이며 이후 Elo로 점수를 갱신합니다. 역사 전투·AI·일반전은 점수에 반영하지 않습니다. 랭크 계정은 브라우저에 저장되며 개인 복구 코드로 옮길 수 있습니다. 복구 코드를 가진 사람은 계정을 사용할 수 있으므로 공개하지 마세요.

일반 쟁탈전·온라인 일반전·전역에는 함선 수와 함대 전력 상한이 없습니다. 쟁탈전의 각 진영은 같은 초기 자금으로 시작하고, 자금과 선소를 확보하면 계속 증원할 수 있습니다. 일반전의 새 건조·건설·증축 시간은 기존의 36%이며 선소 1·2·3단계는 각각 2·3·4척을 동시에 건조합니다. 군영은 단계마다 승조원을 초당 0.8% 충원하고 선소 건조를 지원하며, 수리소는 선체 1%·승조원 0.2%를 회복합니다. 포대·창고·봉수대의 증축은 각각 포격·보급·거점 장악을 강화합니다. 완성된 함선에 집결 지점을 지정할 수 있습니다. 전역의 새 건조는 64초당 1턴, 건물 증축은 50초당 1턴으로 환산해(판옥선 1턴, 거북선 2턴, 대부분의 증축 1~2턴) 휴식과 수리도 빨라졌고 선소 병렬 칸은 4·6·8칸입니다. 새로 시작하는 전역은 시작 함대·포구 수비대·증원이 이전의 2배입니다. 기존 저장 작업의 기간과 지불 비용은 보존합니다. 랭크는 지휘관당 36척·전력 10000과 기존 생산·수리 규칙을 고정해 사용합니다.

전역 함대 합류의 24척 제한과 3D 해전의 30척 제한을 제거했습니다. 전투에 참여한 모든 함선이 직접 출전하고 결과에 반영됩니다. 전역 군영·선소·포대 등은 해전의 시설과 단계로 이어집니다. 역사 시나리오의 출전 함선과 전투 수치는 유지하며, 대표 함선인 거북선은 게임 내 선체와 물리 크기를 길이 50.4m·폭 14.4m로 확대했습니다(판옥선 40m·11.5m). 이는 게임의 미술 방향이며 실제 역사 치수를 주장하는 값이 아닙니다.

장수 초상화 18종은 조선의 두정갑·투구, 일본의 판금 갑옷·가부토, 명의 붉은 갑옷·망토를 구분하는 영화 장면풍 이미지입니다. 생성 프롬프트와 파일 해시는 `scripts/portrait-art-direction.json`에 기록합니다. 거북선 용머리는 사용자 승인 이미지로 Meshy 7.1에서 1회 생성한 원본을 보존하고, 승인된 형태를 로컬에서 1,499·499·179삼각형 LOD로 최적화했습니다. 출처·승인·비용·해시는 `assets-src/dragonhead-2026-10-11/`에 있습니다. 함대 선회 항적, 젖은 해안 암반과 낮은 해무는 기존 관측 규칙과 함께 렌더링합니다.

빠른 생산 규칙에 맞춰 기본 동맹 전역의 진영 소득 배율을 조선 1.0·일본 0.93·명 2.0으로 조정했습니다. 개발 시드와 분리한 500개 시드의 보통 난이도 AI 전쟁에서 조선·일본·명 승률은 31%·39%·31%, 무승부·미종료는 0건이었습니다. 이는 해당 전역 AI 정책의 검증이며 실시간 대전이나 사람 간 균형을 입증하지 않습니다.

새로 시작하는 사람 플레이 전역에서는 조선을 선택하면 동맹 명, 명을 선택하면 동맹 조선의 시작 함대·무료 함대 증원을 약 40%, 진영 수입을 35% 줄입니다. 플레이어 함대와 수비대·유료 건조는 줄이지 않으며, 일본 선택 시 적 연합군에는 적용하지 않습니다. `allySupport.version = player-ally-v1`을 새 저장에 기록하고 무료 증원의 소수분을 다음 증원으로 이월합니다. 기존 저장에는 이 규칙을 추가하지 않습니다. 동맹 파기 시 이후 소득·증원 감축은 중단됩니다.

전역은 목포진·녹도진·방답진 등을 포함한 25지역과 한국 해안 21포구를 사용합니다. 새 포구의 사료 링크는 지역 데이터에 기록하고, 기존 12지역 저장은 함선·항로·자금·RNG를 보존하며 확장합니다. 전역 지도는 역사 전투 선택 화면과 같은 DEM 기반 잉크 지도를 쓰며, 휠로 확대·축소하고 드래그로 이동합니다. 터치에서는 두 손가락으로 확대·이동하고, 폰과 터치 전용 태블릿은 3D 없이 같은 지도 이미지를 씁니다. 지도 위에는 세력별 영토 색과 군영 단계가 보이는 정착지 배지가 있고, 가까이 확대하면 그 군영의 조감도가 도시 카드로 나옵니다(폰은 더 크게 확대할 때만 나옵니다). 병력을 고르고 이동을 누르면 갈 수 있는 항로가 굵은 점선과 방향 표시로 강조됩니다. 지형 자료의 출처는 `public/ui/TERRAIN-CREDITS.txt`에 있습니다. Ctrl(Cmd)+드래그나 지도 옆 "박스 선택" 버튼으로 사각형 안의 함대와 포구 수비대를 한 번에 고르고(Shift를 더하면 추가), 포구 마커를 눌러 수비대를 일괄 선택에 넣고 뺄 수도 있습니다. 고른 병력은 모두 도달할 수 있는 목적지를 한 번 눌러 바로 출동하며, "도착하면 합류"를 켜면 같은 지역에 모인 함대가 하나로 합쳐집니다. 한 포구에 있는 함대는 "모두 합류"로 한 번에 합칩니다. 빈 지도를 눌러도 선택은 유지되고 Esc나 "선택 해제"로 지웁니다. 수비대는 실제 함선과 승조원 상태를 유지한 출동 함대가 됩니다. 지역 전투의 지형은 지역 표식 주변 16 km의 실제 고도(`public/terrain/<지역>.dem`, 출처는 `public/ui/TERRAIN-CREDITS.txt`)로 만들고, 지역마다 숲·바위·논·마을·봉수의 구성이 다릅니다. 자료에 해저 수심이 없어 바다는 해안에서 멀어질수록 깊어지게 만든 값이며 실제 수심이 아닙니다. 일본과 중국 지역의 가옥은 아직 조선식 초가·기와 모델입니다.

비역사 해전의 주력함 시야는 900m, 각 진영 정찰함(협선·고바야·명 소형선)은 1600m이며 같은 팀이 관측을 공유합니다. 섬이 시야를 가리고 밤과 안개는 관측 거리를 줄입니다. 완성된 봉수대는 해안 시야를 넓힙니다. 온라인 서버는 관측되지 않은 적의 위치·시설·생산 정보를 전송하지 않습니다. 전역에서도 주력함은 인접 항로, 정찰함은 두 항로의 정보를 확인합니다. 전역 AI도 같은 시야를 사용하고 미정찰 포구는 공개된 지역 가치로 추정합니다. 전역 현황의 적 함선 수는 관측한 함대만 집계하고 비공개 전력이 포함된 점수는 전쟁이 끝나면 공개합니다.

일반 해전은 전투 시드로 낮·노을·밤·안개·풍랑과 바람을 선택하고 서버와 화면이 같은 파도·시정·조류를 사용합니다. 여수·목포의 회오리와 전용 진형은 지형에 맞춘 게임 설계이며 당시의 실제 조류나 진형을 재현했다고 주장하지 않습니다. 충돌 속도와 진입각, 수선 아래 피격은 선체·승조원·침수·추진·조타 손상에 영향을 줍니다. 승조원의 배수와 수리소에서 복구합니다. 랭크는 고정된 기상과 조류 없는 조건을 사용하고 역사 시나리오는 기존 조건을 유지합니다.

전투 조작: `Ctrl+A` 전체 선택, `Ctrl+1~8` 부대 지정, `Shift+1~8` 선택 함선 추가, `1~8` 부대 선택, 같은 부대를 두 번 선택하면 시점 이동. 왼쪽 부대 패널에서 지정·이름 변경·경로 예약을 할 수 있으며 휴대폰에서는 패널을 접어둘 수 있습니다. `Shift+우클릭`은 최대 16개의 이동 지점을 예약합니다. 바다에 내린 이동 명령은 금빛 깃발로 8초간 표시하고 예약 지점은 번호가 붙은 하늘색 깃발로 구분합니다. 새 이동·정지·공격·진형 명령은 예약을 지웁니다. 진형은 `Alt+1~4`, 속력은 `Alt+5~7`입니다. 온라인의 이동 예약과 건설은 서버가 검증하고 실행합니다.

비역사 모드는 `src/sim/competitive.ts`의 경쟁용 함선 수치를 사용하고, 역사 전투는 기존 카탈로그와 시나리오 보정을 사용합니다. `node scripts/balance-competitive.mjs --cohort=holdout --mode=conquest --seeds=8 --map=hallyeo,gyeonnaeryang --comps=default,heavy,mobile --out=shots/balance/holdout.json`으로 동일 자원·양쪽 출발 위치를 바꾼 AI 검증을 재현합니다. AI 승률은 사람 간 완전한 균형을 입증하지 않습니다. 실제 랭크전은 개인 서버 기록의 복사본에 `node scripts/report-ranked.mjs --file=<ranked.jsonl>`을 실행해 진영별 결과와 출발 위치 편향을 확인합니다. 기권·접속 종료·무효 경기는 전투 밸런스 통계에서 분리됩니다.

서버 랭크 기록은 `RANKED_STORE`로 지정한 JSONL 파일에 저장합니다. 운영 파일은 `/opt/imjin/data/ranked.jsonl`이며 서버 번들과 함께 덮어쓰지 않습니다. 기록 파일은 계정 인증 해시를 포함하므로 비공개로 관리하고, 변경 전 백업하세요. 결과를 두 사람에게 반영하는 기록을 디스크에 확정한 뒤 점수를 알립니다. 서버 재시작 중 미완료 대전과 로딩 실패는 무효 처리됩니다.
